MerchantLookup System - Problem Description

  Current Issue

  The merchantlookup system is completely broken -
  it returns "Uncategorized" for ALL inputs, even
  for merchants that clearly exist in the data files
   (like "Starbucks" which is in the Slovak merchant
   data).

  System Architecture

  Files involved:
  - /home/runner/workspace/lib/merchantLookup.ts -
  Main lookup logic
  - /home/runner/workspace/lib/merchants/countries/s
  k.json - Slovak merchant data
  - /home/runner/workspace/lib/merchants/countries/p
  e.json - Peru/Spanish merchant data
  - /home/runner/workspace/lib/merchants/countries/u
  s.json - US/English merchant data
  - /home/runner/workspace/lib/merchants/global.json
   - Global merchant data
  - /home/runner/workspace/lib/merchants/business-ty
  pes.json - Business type mappings
  - /home/runner/workspace/server/routes/voiceRoutes
  .ts - Voice parsing that calls merchant lookup

  Expected Behavior

  Input: "kupil som si kavu nescafe gold za 5.50"
  (Slovak: "I bought Nescafe Gold coffee for 5.50")
  - Should detect "kava" (coffee) in Slovak merchant
   data
  - Should match to coffee_shops category with
  business_type: "coffee_shop"
  - Should return typical_categories: ["Food &
  Dining", "Jedlo", "Comida"]
  - Final result should be category: "Jedlo" (Slovak
   for Food)

  Merchant Data Structure

  Slovak data (sk.json) contains:
  {
    "coffee_shops": {
      "business_type": "coffee_shop",
      "category_keywords": ["jedlo", "kava",
  "stravovanie"],
      "merchants": ["starbucks", "costa coffee",
  ...]
    }
  }

  Business types (business-types.json) contains:
  {
    "business_type_mappings": {
      "coffee_shop": {
        "typical_categories": ["Food & Dining",
  "Jedlo", "Comida"]
      }
    }
  }

  Lookup Process (6 steps)

  1. Extract merchant name from transcript (often
  fails for non-English)
  2. Check user history (skipped - no userId)
  3. Check learned patterns (skipped - no patterns)
  4. Load merchant data and try direct merchant
  match
  5. Try global merchant data fallback
  6. Context analysis - should find "kava" in Slovak
   keywords but fails

  Critical Issues Identified

  1. File loading - Fixed (files load correctly now)
  2. Context analysis - The
  analyzeTransactionContext function isn't properly
  checking localized keywords
  3. Category mapping - Voice routes should map
  business_type to final category using
  typical_categories
  4. Language detection - Should use country code
  "sk" for Slovak, "pe" for Spanish

  Key Functions

  - lookupMerchant(transcript, countryCode) - Main
  function
  - loadMerchantData(countryCode) - Loads JSON files

  - analyzeTransactionContext(transcript, 
  businessTypes, merchantData) - Should find
  keywords
  - findMerchantMatch(merchantName, merchantData) -
  Direct merchant matching

  Voice Route Integration

  Voice routes call lookupMerchant(transcript, 
  countryCode) and should:
  1. Get merchantResult with business_type and
  typical_categories
  2. Extract category from
  typical_categories[langIndex] where langIndex = 1
  for Slovak
  3. Return the localized category name

  Test Cases

  - Input: "starbucks" → Should return "Jedlo"
  - Input: "kava" → Should return "Jedlo"
  - Input: "tesco" → Should return "Jedlo" (grocery)

  Root Cause

  The context analysis step (Step 6) is the most
  likely failure point. It should detect "kava" in
  the Slovak coffee_shops category_keywords but is
  returning null instead of a proper
  MerchantLookupResult.

  TASK: Debug and fix the merchantlookup system so 
  it properly categorizes transactions using the 
  existing merchant data files.
